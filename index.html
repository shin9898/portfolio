P.15 — 働き方

AI は速くする。止まれる人を残す

道具の一覧ではない。役をまたぐ進め方 ※本人談 + 個人リポジトリ

  • 役割を分ける

    設計・実装・レビューを、同じ手が兼ねない。

    Claude が設計 → Codex が実装 → CodeRabbit がレビュー。ENGAGEMENT で運用を主導。

  • 人が止まれる

    送る・書く・採用する前に、人が確認する。

    CS の返信は案まで。顧客の声の抽出は読み取り専用。本番 DB は書かない。PdM では AI 提案を人がゲート。

  • 判断を残す

    課題設定・リリース判定は、人が検証できる形に。

    自己PRの完成条件と同じ。速さは AI、責任は人。

ハーネスは Claude / Codex / Cursor で共用 workbench: my-copy/。ツール名の羅列はしない。

P.16 — 働き方

メモは入口を一つにする

タスク・目標・学習を、同じ場所で短い周期で閉じる ※本人談

  • 入口は一つ

    本人の仕事も、AI に任せる作業も、同じ場所に起票する。

    プロダクト別に分けたリスト 5 面。平日朝に期限を出し、夜に閉じる workbench: obsidian_kanban.py

  • 短い周期で閉じる

    日次で出す・終業で閉じる。週次で、捨てる候補と来週の賭けを決める。

    テンプレはスキルに固定。機械が下書きし、人が書く範囲を決める workbench: my-copy-goal-os

  • 目標を証拠で見る

    未計測を 0% にしない。上長の FB と 5 種の証拠で判定する。

    学びは日記 → 週次で一般化 → 知識へ。本・一般理解・自社翻訳・実務証拠を混ぜない llm-config: auto-learning.md

Vault 本体はローカルのみで未読。効果の数字とプラグイン構成は公開しない（本人に無し）。

P.17 — 自己PR

逆算で作る

  • 事業成果から逆算して技術境界を越える。フロント・バック・基盤を分断しない。
  • 完成条件は三つ。使える。監視できる。原因を追える。
  • CS で顧客の現場を直接知る。「動く機能」ではなく「運用に乗る機能」から逆算する。
  • ストレス診断・テスト正答・認証。機微なデータは権限・漏洩防止・匿名性を設計から。
  • 本番障害は原因特定から再発防止まで。速さと安全をテストと監視で両立。
  • AI の速さを活かし、課題設定・レビュー・リリース判定は人が検証できる形に。

PDF「自己PR」を短く切った。意味は変えていない。
